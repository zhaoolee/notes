# 2026-10-31：编辑器图片占位与并行上传

- `EditorImageUploadSession` 是当前编辑器实例的共享队列；各批次共用 5 个并发槽位。
  不要对每批分别启动 5 个 worker，否则追加图片会突破总并发限制。
- 待上传图片在正文外保存锚点、文件和预览 URL，`splitEditorContentWithUploads`
  只在编辑器中合并为上传块；便签正文、自动保存和导出不会包含临时占位。
- 异步成功必须读取 session 最新正文，按锚点和原始编号插入。不可使用 enqueue
  时的 React markdown 快照，否则会覆盖上传期间的编辑，或按网络完成顺序乱序。
- 重复文字会让全文最长公共前后缀产生位置歧义。普通文字输入必须传入实际编辑
  文本段范围，并区分该段前后的上传块；图片删除等跨段操作不能误传文字段范围。
- 文件使用 XHR upload progress；传输结束显示 99% 等待后端确认。图片 URL 导入
  没有可靠的字节进度，使用不定进度，不能伪造百分比。
- 上传成功、移除和卸载都释放 blob URL；切换便签时 abort 所有在途请求并清掉
  排队任务，旧请求不得把图片插到新便签。失败保留文件供重试，不占并发槽位。
- `node scripts/verify-editor-image-uploads.mjs` 对构建产物做隔离浏览器验收，真实
  拖入 100 张后再追加 2 张，确认并发峰值为 5；也检查失败重试、文字保留、手机
  布局、取消和便签切换。该脚本不启动 iOS 模拟器、不写日常工作区。
