## 架构事实

- 前端源码当前位于 `src`，后端源码当前位于 `server`。
- `NoteSheet` 和 Markdown 分段逻辑由前端预览、Playwright PNG 导出和离线归档共同复用。
- PNG 导出依赖 Playwright Chromium 打开可访问的前端页面。
- 单容器镜像由 Express 提供前端静态文件；双容器生产环境由 Nginx 代理 API 和图片。
- `storage/images` 是导入图片与已生成 PNG 的持久化边界。
- 账号、按用户隔离的云端工作区和匿名额度使用
  `storage/data/notes-data.json` 持久化；会话使用服务端签名 Cookie。

## 2026-07-26：本地多便签工作区

- 前端状态包含便签集合和当前便签 ID，每张便签独立保存 Markdown、创建时间和更新时间。
- 工作区使用 `notes.workspace.v1` 持久化到浏览器 `localStorage`；旧的 `notes.markdownDraft` 会在首次加载时迁移为第一张便签。
- 大于 `640px` 时使用常驻左侧栏，提供搜索、新建、切换和带确认的删除；项目不再保留中间宽度的平板抽屉布局。
- 侧栏只显示更新时间和从 Markdown 自动提取的标题或第一句话；列表采用 50px 行高、20px 左留白、12px 时间和 14px 标题。选中项仅使用浅背景与单层内阴影，不显示左侧色条或额外顶线。
- 删除最后一张便签时会自动创建新的空白便签，工作区始终至少保留一张。
- 存图、归档、复制和插图都只作用于当前选中的便签；示例内容只用于首次初始化，不再作为正式界面操作。
- 匿名多便签数据只存于浏览器本地；普通用户或超级管理员登录后改用按账号 ID
  隔离的服务端工作区。
- 前端 feedback 覆盖工作区数据校验、标题摘要提取和侧栏结构；浏览器验收确认新建、切换、刷新持久化、搜索与删除流程可用。

- 后端会缓存 Playwright 浏览器启动 Promise；首次启动失败后，即使补装 Chromium，同一后端进程仍需重启才能恢复导出。

  按源地址长度降序执行，避免查询参数地址被基础地址部分替换。
- React 19 服务端渲染会为图片自动输出顶层 preload `<link>`；这种节点不属于
  可粘贴正文，可能被公众号计为失败内容，`POST /api/wechat` 会在返回 HTML 前
  明确移除它。feedback 锁定输出中没有 preload、Data URL 或裁剪列表编号的样式。
- `npm run dev` 会先加载仓库根目录 `.env`；七牛配置再按环境变量、
  `QINIU_CONFIG_PATH`、仓库 `qiniu.json`、相邻
  `upload-local-image-to-qiniu/qiniu.json` 的顺序解析。本机真实凭据保存在被
  Git 和 Docker 构建上下文忽略的 `.env`，文件权限为 `600`；仓库只提交
  `.env.example`。Docker Compose 自动从 `.env` 注入变量，正式生产环境仍应
  使用部署平台的环境变量或 Secret。
- 七牛默认上传入口可能返回 bucket 区域提示；服务会按响应自动切换到对应
  `*.qiniup.com` 入口并在进程内缓存。
- 生产日志曾出现 `upload.qiniup.com:443` 在 TLS 建连前瞬时
  `ECONNRESET`；七牛表单上传仅在没有收到任何 HTTP 响应的网络异常时原请求最多
  重试三次，每次等待响应不超过 6 秒。公开图片仍返回既定的七牛 HTTP 域名，
  不切换代理或改写 Markdown。
- 2026-08-01 使用七牛区域查询接口核验，生产 Bucket 属于 `z2`（华南），返回的
  上传域名依次为 `upload-z2.qiniup.com`、`up-z2.qiniup.com`。当时生产环境未设置
  `QINIU_UPLOAD_URL`，服务先请求只适用于华东的默认 `upload.qiniup.com`，再依赖
  400 区域提示切换到 `up-z2.qiniup.com`。
- 同次生产诊断中，服务器到 `up-z2.qiniup.com` 各 IP 的 TCP 建连只需约
  `1-3ms`，但 TLS 握手实测从 `1.8s` 到 `9.2s` 不等，另有节点超过 `10s`；应用
  的 `6s` 超时包含 DNS、TCP、TLS、上传请求体和响应，因而会在 TLS 阶段主动中止
  健康但偏慢的连接。生产堆栈同时记录了区域切换后的上传超时和复用已缓存区域
  入口后的上传超时。对应代码修复把单次完整上传预算改为默认 `30s`、允许通过
  `QINIU_UPLOAD_TIMEOUT_MS` 在 `10s-300s` 内配置并校验；生产部署还应直接指定
  Bucket 区域查询返回的优先 `QINIU_UPLOAD_URL`，不能只增加对同一短超时入口的
  重试次数。
- 真实图床验收上传了现有测试图片，接口返回 `imageCount = 1`、
  `uploadedImageCount = 1`，公开 URL 返回 `200 image/jpeg`；现有图床域名配置
  是 HTTP；这是当前公众号正文图片的明确产品约定，不能自行替换为本站 HTTPS
