# 桌面与手机界面基准

## 当前视觉基准

桌面版以锤子便签网页版为颜色、细线、字体、纹理和图标基准：

- 页面：<https://yun.smartisan.com/?from=snote#/notes>
- 应用入口：<https://yun.smartisan.com/apps/note/>
- 样式快照：<https://static.smartisanos.cn/cloud/note/css/note-all_4bbfbe751b.css>
- 本地资源说明：[`public/smartisan/web/README.md`](../public/smartisan/web/README.md)

手机版以已连接安卓设备中的锤子便签 4.2.1 为布局、视觉和触摸交互基准。2026-07-28 再次通过 ADB 截图和 UI 层级读取确认：主界面逻辑宽度为 `360dp`，顶栏 `48dp`，列表纸片 `75.3333dp`，左侧固定装订夹 `28.6667 × 75.3333dp`；不得再用桌面网页版的 `62px / 50px` 节奏覆盖手机列表。

## 官方网页实测参数

2026-07-27 在已登录页面中读取 DOM 与计算样式，得到以下基准：

- 顶栏总高 `62px`：内容高 `61px`，底线 `1px #564944`。
- 顶栏渐变 `#827265 → #716053`，阴影 `0 1px 8px rgba(0,0,0,.15)`。
- 分类筛选、列表筛选和正文状态栏均为 `50px`。
- 分类项与便签项均为 `49px` 内容加 `1px #e4dad1` 底线。
- 普通纸面 `#fbf7ed`；选中纸面 `#f1ece1`，只增加 `inset 0 1px 4px rgba(0,0,0,.03)`。
- 栏分隔线 `1px #dcd6ca`；正文状态栏底线 `1px #e3dcd1`。
- 搜索框距栏四周 `10px`，高度 `29px`，圆角 `14px`，背景 `#fcfcfc`，边框 `#e4dad1`，内阴影 `0 1px 4px rgba(0,0,0,.12)`。
- 列表时间 `12px/20px #b9a691`，标题 `14px/20px #635753`，左内边距 `20px`。
- 正文使用 `17px/50px`，内容距左边 `50px`；左纸边为 `25px`，横线每 `50px` 重复。
- 三栏运行时宽度约占视口 `15.72% / 25.83% / 剩余空间`。在 `1622px` 视口下为 `255 / 419 / 948px`。

## 响应式边界

项目只保留两种布局，不提供 iPad 或平板专用布局：

- 大于 `640px`：分类 / 便签列表 / 单一正文工作区三栏。
- 不超过 `640px`：分类浮窗覆盖于便签列表，编辑 / 预览仍使用分层工作区。

官方网页自身设置了 `min-width: 1280px`，直接照搬会让手机只看到被裁切的桌面左上角。因此桌面 Web 对齐样式不能下沉覆盖手机断点；手机使用 APK 顶栏、按钮、搜索框、九宫格纸片、木纹、装订夹和状态图标，页面切换与触摸操作也遵循安卓客户端。

## 手机工作区

`src/App.tsx` 使用 `MobileWorkspaceView` 管理三种视图：

- `notes`：默认显示的便签列表。
- `editor`：选择或新建便签后的独立 Markdown 编辑页。
- `preview`：与编辑器互斥的成品便签预览。

进入便签详情时，地址栏使用
`#note=<便签 ID>&view=editor|preview` 同时记录内容身份和当前视图。选择或新建
便签会新增一条浏览器历史，编辑 / 预览切换只替换当前历史；返回列表会移除 hash。
页面首次载入、浏览器前进后退或用户直接修改 hash 时，都先等待本地 / 云端工作区
完成初始化，再按唯一 ID 选择便签并恢复编辑或预览。仍在回收站中的便签强制进入
回收站预览；找不到 ID 时安全回到全部便签列表并清理失效 hash。URL 改写必须保留
`testData`、主题和页脚等既有查询参数。

手机端新建便签时会记录本次创建的草稿 ID。若用户未写入任何非空白字符就返回
列表，并且工作区仍有其他正常便签，则该空白草稿会被直接丢弃，列表不得残留
“新便签”占位；当前便签同时原子切换到列表中的真实下一条，不能出现占位行与点击
目标错位。若工作区没有其他正常便签，则保留唯一空白便签作为可编辑入口。已经
写入过内容的便签、既有空白便签和回收站内容不会被这条返回逻辑误删。

列表顶栏左侧是设置，中间是当前分类，右侧是新建。点击分类名称会在列表上方打开一个无暗色遮罩的锚定浮窗，正文、列表和滚动位置都保持不变。浮窗包含全部便签、加星便签、回收站和自定义文件夹，底部提供编辑、名称排序和新建文件夹；选择分类、再次点击标题、点击浮窗外或按 `Escape` 都会收起。

浮窗参数来自 `1080 × 2400`、480dpi 安卓真机上的原版锤子便签：换算到 CSS 逻辑尺寸后左右各约 `31px`，距内容区顶部约 `16px`，圆角约 `8px`；分类行高 `48px`、分隔线 `1px`，底部操作区约 `45px`。浮窗使用白色纸面、浅灰细线和双层轻阴影，不移动或重排 `body` 主体。

手机版使用 `48px` APK 顶栏和 `75.3333px` 九宫格纸片列表。便签行显示时间、单行标题、星标、置顶和图片状态；文字从纸片左侧 `52px` 开始，时间为 `12px`，标题为 `16.5px/30px`。左侧金属装订夹保持 APK 的 `28.6667 × 75.3333px` 透明画布，作为列表级固定轨道独立于 sortable 便签存在；拖拽开始时整条轨道向左收起 `19px`，释放后回弹，普通便签拖拽时只有纸片本体移动。

列表背后的木纹必须由根布局承载一张并铺满整个可视区域，不能按素材的
`160 × 273dp` 固有尺寸横向或纵向重复。2026-07-31 通过 ADB 再次确认：
`activity_notes.xml` 的 `mainRootLayout` 直接使用
`android:background="@drawable/note_background"`，列表层本身透明；真机
`1080 × 2400` 截图中木纹从屏幕左边连续延伸到右边，没有多列拼接接缝。
Web 手机断点因此使用根 `.app-layout` 的单张
`no-repeat / 100% 100%` 背景，并让 `.note-sidebar` 与 `.note-list` 保持透明。
暖白和暗黑主题以及手机成品预览舞台遵守同一规则。

移动端普通便签静止按住约 `220ms` 即可开始排序，并允许 `12px` 内的手指抖动；
拖动锁定纵轴并使用脱离列表滚动容器的浮层，避免卡片靠近屏幕边缘时被裁切。
可排序卡片及其全部子元素禁止文本选择、图片拖拽和 WebKit 长按菜单，长按只进入
便签排序，不触发 iPhone 的文字选区或内容预览。
页面高度由纵向 flex 剩余空间承载，同时通过 `viewport-fit=cover` 和四周安全区变量
适配 iPhone 刘海、圆角与底部 Home Indicator。

手机版是固定一倍比例的应用式工作区，不允许浏览器双指缩放。入口 viewport 同时
声明 `initial/minimum/maximum-scale=1` 和 `user-scalable=no`；由于 iOS 的
WebKit 可能忽略 viewport 的缩放上限，手机断点还必须在 `html / body / #root`
使用显式 `touch-action: pan-x pan-y`，保留页面横纵拖动能力但不包含
`pinch-zoom`。不能改成 `touch-action: manipulation`，该值仍允许双指缩放。
移动端文本输入框、textarea 和 select 的字号不得小于 `16px`，避免 iPhone 聚焦
小字号表单时自动把页面放大。

iOS Safari / Chrome 展开顶部地址栏、恢复页面或显示软键盘时，
`visualViewport.height` 会变化。iOS 26 在系统键盘、Emoji 键盘和第三方键盘之间
切换时还会增大 `visualViewport.offsetTop`。移动端应用壳保持固定定位，同步可视
视口高度和纵向偏移量，
并在 `pageshow`、横竖屏切换以及可视视口尺寸变化时重新计算。应用壳的原点必须
始终固定在 `top: 0; left: 0`：不得把 `visualViewport.offsetTop` 写入 `top`、
`transform` 或用它平移整个页面，也不得在 `visualViewport.scroll` 中强制
`window.scrollTo(0, 0)`。应用壳使用 border-box 布局，把高度设为
`visualViewport.height + visualViewport.offsetTop`，同时把同一个 offset 作为
顶部内边距；这样实际内容高度仍等于可视视口高度，壳体底部也始终贴住键盘上方，
而命中区域会随正常布局一起移动。若只同步 height，键盘二次切换后壳体会提前在
可视视口中结束，快捷栏下方露出大块木纹，顶栏和正文还会逐步漂到屏幕上方。
iOS 浏览器的地址栏动画会让 offset 短暂变化；短文和键盘类型切换主要触发
`resize`，但至少 50 行的长文在点击中段或后段时，还会在 resize 之后通过
`visualViewport.scroll` 完成第二阶段光标避让。因此 resize 和 scroll 都只同步
上述两个 CSS 变量；scroll 处理不得调用 `window.scrollTo`、改写应用壳的
`top / transform`，也不得主动移动编辑器滚动位置。

水平方向必须始终以布局视口的 `left: 0; right: 0` 铺满，安全区交给
`env(safe-area-inset-left/right)`。不得把 `visualViewport.offsetLeft / width`
直接写入应用壳：iOS 26 Safari 的浮动浏览器控件和边缘回弹会瞬时报告较窄的可视
宽度。真机录屏中应用壳右边界从 `1320px` 移到 `1232px`；按设备 `3×` 比例，
等价于整页从 `440px` 缩到约 `410.7px`，右侧露出约 `29.3px` 空带。页面根节点
继续禁止滚动，只有便签列表、编辑器和预览区允许各自滚动。

普通便签支持安卓版的横滑删除操作：手指向右滑动纸片时，纸片最多移动
`66px`，从左侧露出距列表边缘 `22px`、尺寸
`73.6667 × 35.6667px` 的原版删除图标；位移达到 `28px` 后释放会吸附展开，
向左滑回或点击其他便签会收起。同一时间最多展开一条，纵向滚动优先，横滑
完成后的点击不会误进入正文。点击删除图标仍进入项目已有的软删除确认流程，
回收站不提供横滑删除。

详情顶栏左侧返回不会与右侧操作争夺空间。编辑态右侧是插图和完成，预览态右侧是删除和分享；设置只在列表页出现。顶栏下的 `50px` 状态栏显示文件夹、更新时间、字数和编辑/预览切换。正文左侧 `25px` 深色纸轨必须向上贯穿整个状态栏；状态栏和正文共用同一宽度变量、纹理与右侧分隔线，文件夹控件位于纸轨右侧 `10px`，不能出现上下错位或中途断开。

预览态的分享入口使用原版“请选择操作”底部操作层，而不是悬浮卡片或网页下拉菜单。
移动面板左右与底部贴合视口，只在顶部保留 `16px` 圆角；`52px` 标题栏居中显示
“请选择操作”，右侧关闭键不画按钮边框。面板使用中性浅灰背景，动作区左右留白
`16px`、顶部留白 `20px`、纵向间距 `18px`；每个动作是至少 `58px` 高、
`10px` 圆角的纯白卡片，只显示居中主文案，不显示 Web 能力说明。背景遮罩使用
接近原版截图的深灰层，面板自底部轻微上移进入，并遵守系统减少动态效果设置。
项目只列出真实已有的复制文字、复制到公众号、图片分享和离线归档能力，不伪造
新浪微博、邮件或知识库入口。暗黑主题保持同一几何，仅替换为已验证的锤子暗黑色板。

设置页沿用桌面相同的信息架构；手机端把桌面左侧类别栏转换为顶部横向滚动栏，
正文区域独立纵向滚动。账号登录只放在“账号与同步”，手机顶栏和分类浮窗不重复
提供入口。登录后该类别显示当前账号、同步状态、修改密码和退出登录；修改密码使用
独立弹窗。匿名和登录用户都可在该类别导出全部便签；处理期间显示便签收集、ZIP
生成和下载进度，完成后通过系统分享或浏览器下载保存。AI 辅助审阅放在“工具与扩展”的“智能工具”分组，Hermes 下载放在同页的
“外部扩展”分组；登录状态可下载已授权的
`notes-workspace-api.zip`、复制供多台电脑使用的当前链接，或通过独立按钮主动
重置链接；点击重置后必须先确认旧链接会立即失效，取消确认时不得发起重置。
普通复制不会让旧地址失效，匿名状态引导先登录。

登录且启用 AI 后，详情顶栏的 AI 按钮必须兼容软键盘仍展开的 iOS Chrome。
触摸按下阶段就捕获当前便签并打开审阅，不能等待可能被 `visualViewport` 重排取消的
`click`；同时主动结束正文焦点，让键盘正常收起。AI 审阅层通过 React portal
直接挂到 `document.body`，不能嵌在移动端固定定位且 `overflow: hidden` 的
`.app-layout` 内，否则 WebKit 可能把全屏弹层裁掉。桌面鼠标和键盘激活仍走标准
`click`。

设置“个性化”类别提供便签底部显示，交互参考锤子便签 `4.2.1` 的
“Footer Display”：
进入二级页后先显示一张缩小的便签页脚预览，再编辑“发送来源”和 `via` 两段文本。
原版只允许在两张预设卡片间切换，Web 版扩展为各 `80` 个字符以内的自由输入，
内容会随输入实时更新预览。缩略图的双框外沿必须保留四个 `6px` 小方格，其中心
准确落在外框四个交点上，不能只画两层矩形。Logo 区允许上传 PNG、JPG、WebP
或 GIF，并可单独恢复默认锤子图；“恢复默认页脚”同时复位 Logo 和两段文本。
空字符串代表隐藏对应文字；全部设置会持久化并同步用于成品预览、PNG 导出、
离线归档和公众号富文本。

编辑器使用安卓版 `16px/42px` 正文节奏和 `39px / 18px` 左右留白。2026-08-01
在 iPhone 15 Pro / iOS 17 Safari 模拟器中确认：同一个 textarea 的第一行原生
插入点约为文字高度，但第二、第三及后续行即使含有文字，也会被 WebKit 画成接近
完整 `42px` 行框的高度；问题不是空行特例。CSS 无法独立指定系统 caret 高度，
向空行加入零宽字符也不能修复后续有字行。

正文仍由原生 textarea 承担输入、换行、选区、剪贴板、键盘和无障碍语义。移动端
仅在 textarea 聚焦且 selection 折叠时，把系统 caret 设为透明，并根据同字体、
同字号、同宽度、同 padding 和同 `42px` 行高的不可见测量层定位一个固定
`22px` 高的暖棕插入点。测量层只包含当前插入点之前的临时文本，不可见、不接收
事件，也不进入 Markdown、剪贴板或持久化数据。桌面端不启用该适配。

一旦 selection 非折叠、指针开始选字或输入法处于 composition 状态，固定插入点
立即隐藏并恢复 textarea 的系统 caret；选区背景、系统端点、拖动、复制和剪切菜单
始终使用浏览器原生实现，不绘制自定义选区端点。`--editor-line-height: 42px` 继续只
负责正文与横线节奏，横线位于每个行框最后 `1px`。网页不得为了追逐光标边界而
平移横线、文字或 textarea；这种补偿会把首个可见行框截短，并让文字失去相对
横线的垂直居中。
移动端固定使用
`--editor-rule-offset-y: 0px`，纸张横线从正文原点开始，首行和后续行都保持完整
`42px`；固定插入点在各行框内垂直居中。左纸轨的纵向位置是
`-scrollTop + rule-offset`，两层必须一起移动，不能只偏移正文。不能复用高度为
`50px` 的桌面
`grid_6e4a41eefc.png`，否则文字、系统光标与横线每行累积偏移 `8px`。
左侧纸轨使用的 `edge_004e88bdf2.png` 固有高度同样是 `50px`，移动端必须缩放为
`5px × 42px`，并用 textarea 的负 `scrollTop` 同步背景纵坐标；否则纸轨格线会在
正文修正后继续与正文横线错位，滚动时还会再次脱节。正文横线自身必须保留
`background-attachment: local`，挂在正文流的滚动容器上与文字和图片共同滚动；
暗黑主题重画横线时也不能通过 `background` 简写丢失该属性。

编辑态不能只显示 `![图片](...)` 字符串。只要正文含 Markdown 图片或 HTML
`<img>`，解析器就把 Markdown 拆成“原生 textarea 文本段 / 图片块 / 原生
textarea 文本段”，图片作为独立块出现在原始位置，源码标记仍原样保存在便签中。
所有块位于同一个纵向滚动流，图片不能固定在编辑器底部，也不能另画横向缩略图栏。
图片加载后按自然宽高比铺满纸张正文区域；手机端外框左边距
`25px + 7px`、右边距 `25px`，白色装裱层带轻微边框和阴影。图片右上角突出一个
`51px` 圆形三横线操作柄，位置为 `top: 6px / right: -27px`。点按图片本身后，
图片使用 `12px` 模糊，左上角显示五个 `51px` 原版按钮；按钮按原版用
`-11.5px` 负间距相互叠放，依次为删除、编辑标注、下载、放大和裁剪。

删除直接移除当前图片源码；编辑标注在图片下方显示输入框，并实时改写 Markdown
图片的 `[]` 或 HTML 图片的 `alt`；下载保存原图；放大进入黑底 `1 / 1` 预览；
裁剪先把外站图片导入同源，再用可移动、四角可缩放的裁剪框生成新 PNG，并只替换
当前图片 URL。新插入图片使用空标注 `![](...)`，不能自动显示“图片”占位说明。

三横线操作柄的短按仍把系统光标移到图片后的文字段；按住拖动则按正文可见行计算
落点，显示插入指示线，并允许把图片移动到某个换行前后。接近滚动区上下边缘时自动
滚动。图片前一段末尾按 Delete、后一段开头按 Backspace 仍会删除相邻图片源码标记。

每个文本段仍是系统原生 textarea，不使用 `contenteditable`，也不绘制第二套可见
文字或自定义选区。多个图片前后的 textarea 共用一个不可见定位测量层和一个固定
高度插入点；原始文本不再加入任何零宽占位。文本段高度按 `42px` 行框自动展开；
图片块连同上下外边距会补齐到
`42px` 的整数倍，使图片后的 textarea 起点重新落回横线网格，避免图片导致后续
光标与横线相位错开。

最后一个文本段在正文结束后固定保留两个完整行框的不可输入纸面留白，使用
`calc(var(--editor-line-height) * 2)` 跟随当前平台行高；因此滚动到最底部时，正文
最后一行始终位于倒数第三个行框。桌面对应 `100px`，手机对应 `84px`，不能用固定
像素值让手机只剩不足半行的尾部空间。图片位于正文末尾时仍由其后的空文本段承载
这两个行框。

直达带 `#note=...&view=editor` 的手机地址时，登录态和工作区恢复完成前编辑面板仍
以 `display: none` 挂载。此时 textarea 的 `scrollHeight` 为 `0`，自动高度逻辑
不得把正文写死为一行；编辑滚动区从零宽恢复为可见尺寸后必须重新测量。项目使用
`ResizeObserver` 观察编辑滚动区，并在首次测量后再稳定一次因纵向滚动条出现而
产生的文字换行变化。重算继续保存和恢复正文 `scrollTop`，避免修复首屏裁切时重新
引入输入跳顶。

软键盘弹出时，编辑器与键盘之间显示一行 Markdown 快捷输入栏；键盘收起后该栏
同步消失。原版真机栏高 `128px = 42.6667dp`，五个按钮各占
`216px = 72dp`，顺序和文案固定为 `# Title`、`[Center]`、`- List`、
`**Bold**`、`> Quote`。工具栏通过阻止按钮的 `pointerdown` 抢焦点来保留
textarea 光标、选区和软键盘。

按钮语义按锤子便签 `4.2.1` 实测实现：标题在 `# / ## / ###` 之间循环；
居中以方括号包住当前行，空行时把光标放在括号内；列表和引用只添加一次行首
前缀，回车自动续行，在空项目上再次回车退出；加粗在折叠插入点添加一个 `**`
并把光标放在标记后，有选区时用前后两组 `**` 包裹并继续选中原文字，连续点击
允许继续嵌套星号。桌面端不显示该工具栏。

所有平台的正文统一使用 textarea，并显式声明普通便签语义：
`name="note-content"`、`aria-label="便签正文"`、`autocomplete="off"` 和文本
输入模式，不能携带 `username`、`current-password`、`new-password` 或
`one-time-code` 等自动填充用途。真正的登录和修改密码弹窗继续使用标准密码
自动填充字段。

iOS Chrome 的钥匙、银行卡、地址以及输入框上一项/下一项按钮属于浏览器原生输入
附件，不在网页 DOM 中。页面只能用正确的字段语义减少误判，不能通过 CSS、
JavaScript 或替换编辑控件可靠隐藏。Chrome iOS 仍可能忽略
`autocomplete="off"`，银行卡入口需由用户在 Chrome“设置 → 付款方式”中关闭
“保存并填充付款方式”。

不得为了隐藏上述原生附件把正文切换为 `contenteditable`。2026-07-31 真机验证表明，
该方案既没有移除 Chrome 的手动填充入口，又破坏了 textarea 已验证的
`42px` 行高、纸轨相位、系统光标与原生选区，并额外触发上一项/下一项附件。
编辑体验和纸张对齐优先于无法由网页控制的浏览器工具栏。

文本选区沿用原版的暖棕纸感。参考图中未选纸面约为 `#faf7ee`，选区约为
`#e8e0d5`，插入点约为 `#a68b75`；因此网页使用
`rgba(166,139,117,.20)` 作为 `textarea::selection` 背景，固定插入点与恢复时的
系统 caret 都使用 `#a68b75`。选区端点、拖动和剪切/复制菜单全部交给 iOS、安卓
或浏览器原生控件。

iOS 长按空格进入键盘触控板模式时，WebKit 会直接移动 textarea 的原生 selection。
页面监听 `document.selectionchange` 保存最新 `selectionStart / selectionEnd`，供
Markdown 快捷键和插图操作复用，并同步唯一固定插入点的位置。页面不得绘制选区
端点；selection 展开时只保留系统选区与手柄。

## 分类、置顶和回收站

- 全部、加星、文件夹分类自动排除已删除便签。
- 普通删除将便签移入回收站；回收站支持恢复和带确认的永久删除。
- 删除自定义文件夹只解除归属，不删除其中便签。
- 置顶便签始终位于普通便签之前，新置顶内容进入置顶组最前。
- 置顶组不可拖拽；取消置顶后返回原先保留的普通排序位置。
- 搜索结果和回收站不允许拖拽，避免产生不明确顺序。

## 验收重点

- 桌面三栏比例、62px 顶栏、50px 筛选/状态行和 50px 列表行与官方网页一致；这些参数不得覆盖手机断点。
- 选中列表项没有侧边色条，只使用 `#f1ece1` 和极浅内阴影。
- PC 默认只显示编辑器，通过状态栏下拉框切换到预览。
- 手机首次打开显示列表；点击当前分类名称打开覆盖于列表上方的分类浮窗，列表不得隐藏、位移或重置滚动位置。
- 手机点击便签只进入编辑器；编辑与预览互斥，返回按钮始终完整可点。
- 手机新建空白便签后直接返回时，“新便签”占位必须消失；点击任意可见行必须打开
  该行自己的 ID 和正文。
- 手机预览必须显示成品便签，不能只显示空木纹。
- 新置顶内容排在普通便签之前；置顶组禁拖，取消置顶恢复普通排序。
- 手机列表左侧显示固定金属装订夹轨道；拖拽时轨道只向左收起，不随单张便签移动。
- 手机普通便签向右横滑最多 `66px` 后露出左侧原版删除图标；向左回滑、滚动或点击其他便签会收起。
- 手机列表为 `75.3333px` APK 纸片，装订夹为 `28.6667 × 75.3333px`，不是网页版 `50px` 平面行。
- 手机木纹由根布局的一张背景铺满，列表层透明；不得按 `160 × 273px` 重复平铺。
- 手机页面固定为一倍比例，双指不能缩放；聚焦任何文本输入控件也不能触发 iPhone
  的表单自动放大。
- 普通便签拖拽只移动便签本体，不带额外透明容器或装饰阴影。
- 手机 Markdown 快捷栏只随软键盘显示，固定 `42.6667px` 高、五等分，点按后不得让编辑器失焦或收起键盘。
- iOS 26 在系统、Emoji、拼音或第三方键盘之间反复切换时，顶栏、状态栏和正文仍
  留在可视区内，快捷栏下方不得出现由 `visualViewport.offsetTop` 造成的大块木纹空带。
- 键盘验收不能只用一行短文：至少写满 50 行，分别滚到并点击靠前、中间和靠后的
  可见行（基准为第 5、25、45 行）唤起键盘；当前行、顶栏、正文和快捷栏必须同时
